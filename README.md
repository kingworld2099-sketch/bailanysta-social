# Bailanysta

Социальная сеть, где ты видишь не тех, на кого подписан, а тех, кто **прямо сейчас в твоём
городе и в том же состоянии, что и ты**. Одним нажатием отмечаешь свой вайб — лента
показывает посты людей из твоего города с тем же вайбом. Никаких подписок и заявок в друзья:
связь возникает из совпадения в моменте — и из осознанного решения довериться конкретному
человеку, а не автоматически.

**Живое приложение:** https://bailanysta-social.vercel.app
**Демо-вход:** логин `demo`, пароль `demo1234` (или кнопка «Войти как демо» — без ввода данных)

Без входа приложение не показывает ничего, кроме формы входа и регистрации с описанием
проекта — ни ленты, ни профилей, ни поиска. Внутри тоже приватно по умолчанию: логин,
место встречи и контакт скрыты от всех, пока человек сам не отправит запрос на связь, его
не примут и получатель не нажмёт «Доверять» — подробнее в разделе
«Приватность и связь по запросу» ниже.

## Установка и запуск

```bash
npm install        # заодно сгенерирует Prisma Client (postinstall)
npm run db:push     # применить схему к базе
npm run seed        # наполнить базу демо-данными (15 пользователей + demo, посты, лайки, комментарии)
npm run dev          # запуск разработки — http://localhost:3000
```

Перед этим создайте `.env` по образцу `.env.example`:

```
DATABASE_URL=            # пулинговая строка Neon (с -pooler в хосте)
DIRECT_URL=              # прямая строка Neon, для миграций
SESSION_SECRET=          # любая длинная случайная строка
AI_API_KEY=              # ключ Anthropic — только для поиска по смыслу, без него он тихо откатывается на обычный
BLOB_READ_WRITE_TOKEN=   # токен Vercel Blob (создаётся вместе с Blob-хранилищем в проекте)
CRON_SECRET=             # секрет для ежедневной очистки просроченных фото
```

```bash
npm run build       # проверка сборки перед деплоем
```

## Приватность и связь по запросу

Доступ и видимость намеренно устроены строже, чем в обычной соцсети — это ключевая фишка
проекта, а не побочный эффект.

- **Гость не видит ничего**, кроме `/login` и `/register` с описанием идеи. Лента, профили,
  поиск — только для вошедших.
- **В ленте видно имя, город, вайб и текст поста** — этого достаточно, чтобы решить, интересен
  ли человек. Логин, место встречи и контакт не показываются, пока не выполнены оба следующих
  условия.
- **Запрос на связь.** Под чужим постом — кнопка «Хочу законнектиться» (не больше 10 запросов
  в сутки на пользователя). Получатель видит имя, город, чем занимается, о себе и текст поста
  и решает: принять или отклонить. Отклонил — отправитель видит «Отклонено», без объяснений,
  и повторный запрос на этот же пост невозможен.
- **Доверие — отдельный, осознанный шаг.** Само принятие открывает только мини-чат на 24 часа —
  **не** логин, место и контакт. Они раскрываются, только когда получатель поговорил с
  человеком и сам нажал кнопку «Доверять» рядом с его именем. Доверие одностороннее: я вижу
  скрытые данные того, кому доверяю, независимо от того, доверяет ли он в ответ, и оно не
  отзывается и не истекает вместе с чатом.
- **Мини-чат** живёт ровно 24 часа с момента принятия запроса, дальше переписка недоступна
  и история нигде не хранится. Обновление — поллинг раз в 5 секунд, без WebSocket. Любая из
  сторон может завершить чат досрочно кнопкой «Завершить» — это одновременно блокирует
  собеседника: посты друг друга больше не видны, новый запрос отправить нельзя.
- **@упоминания тоже под замком.** Отметить в посте можно только того, с кем уже связаны;
  автодополнение при наборе `@` показывает лишь таких людей. Если кто-то всё же упомянут в
  тексте (например, вручную), читатель увидит рабочую ссылку `@логин`, только если сам
  доверяет этому человеку — иначе на месте отметки просто `@•••`.

## Процесс проектирования и разработки

Идея прошла через несколько версий, прежде чем осесть в текущем виде:

- Первая версия концепции строилась вокруг постинга сразу после смены. Отказались: автор
  работал барменом и знает, что в три ночи у человека нет сил ни на что — это не тот момент,
  когда хочется писать посты.
- Рассматривали статичные интересы в профиле (музыка, кино, животные). Отказались: анкета
  врёт и почти не меняется, а состояние человека меняется каждый день — фильтр по нему
  остаётся живым, а не превращается в очередной список тегов «инди-рок, кофе, путешествия».
- Рассматривали хэштеги для поиска. Отказались: индустрия ушла от них к пониманию смысла
  текста, хэштеги в 2026 году — устаревающая механика.
- Отказались от геолокации в пользу текстового поля «город» — ради надёжности у проверяющего:
  браузерные разрешения на геолокацию легко ломаются и дают пустую ленту в самый неподходящий
  момент.
- Отказались от внутренних личных сообщений: реальная коммуникация всё равно уходит в
  мессенджеры, поэтому в профиле просто ссылка на телеграм/инстаграм. Это решение позже
  пересмотрели частично: добавили мини-чат, но только как временный шаг к обмену контактом —
  без вложений, без истории, с жёстким сроком жизни в 24 часа. Полноценные личные сообщения
  так и не стали частью продукта.

Порядок реализации намеренно нестандартный: сначала пустой проект был доведён до рабочей
ссылки на Vercel (Neon + деплой + первый коммит), и только потом писались функции — чтобы
все проблемы со сборкой и переменными окружения вылезли в спокойный момент, а не за час до
дедлайна.

## Уникальные подходы

- **Лента строится на совпадении состояния, а не на подписках.** Показывает не тех, кого ты
  выбрал читать, а тех, кто рядом и в похожем настроении прямо сейчас.
- **Нельзя посмотреть чужой вайб, не заявив свой.** Переключатель вайба у вошедшего
  пользователя не просто фильтрует ленту — он меняет его собственное состояние. Посмотреть
  весь город, не переключая себя, можно только через отдельный режим «Все».
- **Счётчик активности учитывает свежесть статуса**, а не всех когда-либо зарегистрированных:
  считаются только те, кто отмечал вайб за последние 48 часов (`ACTIVE_WINDOW_HOURS`).
- **Фото к посту живёт 8 часов.** Место и время в посте — это «прямо сейчас», а не архив,
  поэтому и фото не должно превращаться в старую переписку: оно перестаёт показываться
  через `PHOTO_EXPIRY_HOURS` (по умолчанию 8), а раз в сутки задача Vercel Cron
  (`/api/cron/cleanup-photos`) реально стирает файл из хранилища.
- **Место — ссылка на 2ГИС по тексту, а не встроенная карта.** По условиям задания карты,
  координаты и геолокация исключены, но пользователю всё равно нужно понимать, что это за
  место. Клик по названию открывает поиск в 2ГИС в новой вкладке — как ссылка на телеграм
  в профиле, без единой строчки геокода на нашей стороне.
- **Онбординг объясняет реальные элементы интерфейса, а не абстрактный слайд-шоу.** После
  регистрации человек попадает на свой профиль, где по очереди подсвечиваются именно логин,
  город, вайб и контакт — с объяснением, зачем поле нужно и что из него скрыто от посторонних.
  Затем то же самое продолжается в ленте: вайб-переключатель, публикация, запросы на связь,
  поиск. Тривиальные поля вроде имени и фамилии не поясняются — тур не тратит время там, где
  и так всё понятно.
- **Упоминания по логину, а не по имени.** Имя и фамилия не уникальны — два человека могут
  зваться одинаково (и на живом сайте так уже случилось). Поэтому `@упоминание` в посте всегда
  разрешается в конкретный `username`: автодополнение при наборе `@` показывает имя, фамилию
  и логин каждого совпадения, чтобы можно было выбрать нужного человека среди тёзок.

## Компромиссы

- Город хранится строкой, а не геокоординатами — проще, надёжнее, не требует разрешений
  браузера.
- Фильтрация ленты идёт через связь с автором (`Post.author.city`), без дублирования города
  в самом посте — на масштабе этого проекта это проще и не создаёт риска рассинхронизации
  данных при переезде пользователя в другой город.
- Своя авторизация (bcryptjs + подписанный JWT в cookie) вместо готового решения вроде
  NextAuth — меньше возможностей «из коробки», зато весь путь пароля и сессии полностью
  объясним, без магии сторонней библиотеки.
- Доверие в чате — ручное и одностороннее, без автоматического отзыва или срока действия.
  Это осознанно: как только человек решил довериться, отбирать это решение по таймеру было бы
  контринтуитивно. Отозвать доверие можно только через блокировку (кнопка «Завершить» в чате).
- ИИ-поиск по смыслу (Claude, `claude-haiku-4-5`) — бонусный пункт, реализован поверх обычного
  поиска, а не вместо него: пользователь сам включает переключатель «Искать по смыслу».
  Обычный поиск по подстроке остаётся поведением по умолчанию и работает без внешнего API —
  сознательный компромисс, чтобы отказ модели или отсутствие ключа никогда не оставляли
  человека без результатов.

## Известные баги и проблемы

- Счётчик «сейчас в городе» считает только статусы за последние 48 часов, поэтому на
  засеянных демо-данных он будет плавно уменьшаться со временем, пока кто-то не зайдёт
  и не переключит свой вайб заново.
- Нет ограничения частоты запросов на посты и лайки — теоретически возможен спам с одного
  аккаунта. Запросы на связь ограничены отдельно и жёстко: не больше 10 в сутки на пользователя.
- Neon на бесплатном тарифе «усыпляет» базу после простоя: самый первый запрос после паузы
  может занять несколько секунд, а в редких случаях — вернуть ошибку соединения, которая
  пропадает сама при повторной попытке. На активном сайте, когда база уже «тёплая», это
  не заметно.
- Редактирование поста не меняет его вайб — пост навсегда остаётся с вайбом, который был
  у автора в момент публикации, даже если текст потом отредактирован.
- Очистка просроченных фото в хранилище идёт раз в сутки (ограничение бесплатного тарифа
  Vercel Cron), а не сразу через 8 часов. В самой ленте фото пропадает вовремя — от текста
  до фактического стирания файла из Blob-хранилища проходит до суток простоя впустую, но
  это не видно пользователю.
- Фамилия появилась позже, чем поле «Имя» — у аккаунтов, зарегистрированных до этого, всё
  имя целиком лежит в поле «Имя», а «Фамилия» пустая. Ничего не ломается (полное имя всё
  равно отображается верно), но разделить их автоматически нельзя — сплит по пробелу ломает
  имена из нескольких слов, поэтому просто оставили как есть.
- Упоминание рендерится ссылкой у любого текста вида `@логин`, даже если этот пользователь
  ничего не выбирал, а просто написал «email@service» или похожую строку без пробелов —
  разбор чисто по регулярке, без проверки, что перед `@` не было буквы.
- Приватность через `@упоминание` работает только для авто-подставляемой ссылки на логин.
  Если человек вручную впишет в текст поста чужой логин или другие узнаваемые детали, это
  обычный текст поста — система не редактирует и не цензурирует контент, который автор
  сознательно опубликовал.
- ИИ-поиск по смыслу — реальные обращения к платному API Anthropic, без кэширования
  одинаковых запросов и без отдельного лимита на пользователя (кроме общего таймаута
  в 8 секунд и отката на обычный поиск при ошибке).

## Обоснование выбора стека

- **Next.js (App Router) + TypeScript** — фронтенд и бэкенд в одном проекте. Требование
  «интегрируйте свой API» закрывается естественно: серверные маршруты в `app/api/...` — это
  и есть бэкенд, без отдельного сервера.
- **Vercel + Neon** — разворачиваются бесплатно и за минуты. Neon отдаёт отдельную пулинговую
  строку подключения для serverless-окружений, что важно для Vercel.
- **Vercel Blob** — для фото к постам. Тот же дашборд, что и у деплоя и Neon, не нужен ещё
  один сторонний сервис и ещё один набор ключей.
- **Своя авторизация** (bcryptjs + jose) вместо NextAuth — меньше магии, каждый шаг
  (хеширование пароля, подпись и проверка JWT) можно объяснить на защите одной фразой.
- **Claude (Anthropic) для ИИ-поиска** — вызывается только с сервера (`lib/ai-search.ts`),
  ключ `AI_API_KEY` не попадает в клиентский бандл и не коммитится в репозиторий.
- **Prisma 6.19.3, а не последняя мажорная (8.x rc).** На момент разработки `npm install prisma`
  подтягивал `8.0.0-rc.13` — релиз-кандидат, в котором из `schema.prisma` убрали `url`/`directUrl`
  в пользу отдельного `prisma.config.ts` и драйвер-адаптеров. Для курсового проекта это
  неоправданное усложнение, поэтому версия зафиксирована на последней стабильной, которая
  поддерживает привычную схему из задания.
