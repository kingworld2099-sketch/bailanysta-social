# Bailanysta

Социальная сеть, где ты видишь не тех, на кого подписан, а тех, кто **прямо сейчас в твоём
городе и в том же состоянии, что и ты**. Одним нажатием отмечаешь свой вайб — лента
показывает посты людей из твоего города с тем же вайбом. Никаких подписок и заявок в друзья:
связь возникает из совпадения в моменте.

**Живое приложение:** https://bailanysta-social.vercel.app
**Демо-вход:** логин `demo`, пароль `demo1234` (или кнопка «Войти как демо» — без ввода данных)

Гость видит всё содержимое без входа: ленту, профили, поиск. Форма логина не встаёт на пути.

---

## Установка и запуск

```bash
npm install        # заодно сгенерирует Prisma Client (postinstall)
npm run db:push     # применить схему к базе
npm run seed        # наполнить базу демо-данными (15 пользователей + demo, посты, лайки, комментарии)
npm run dev          # запуск разработки — http://localhost:3000
```

Перед этим создайте `.env` по образцу `.env.example`:

```
DATABASE_URL=      # пулинговая строка Neon (с -pooler в хосте)
DIRECT_URL=        # прямая строка Neon, для миграций
SESSION_SECRET=    # любая длинная случайная строка
```

```bash
npm run build       # проверка сборки перед деплоем
```

## Процесс проектирования и разработки

Идея прошла через несколько версий, прежде чем осесть в текущем виде:

- Первая версия концепции строилась вокруг постинга сразу после смены. Отказались: автор
  работал барменом и знает, что в три ночи у человека нет сил ни на что — это не тот момент,
  когда хочется писать посты.
- Рассматривали статичные интересы в профиле (музыка, кино, животные). Отказались: анкета
  врёт и почти не меняется, а состояние человека меняется каждый день — фильтр по нему
  остаётся живым, а не превращается в очередной список тегов «инди-рок, кофе, путешествия».
- Рассматривали хэштеги для поиска. Отказались: индустрия ушла от них к пониманию смысла
  текста, хэштеги в 2026 году — устаревающая механика.
- Отказались от геолокации в пользу текстового поля «город» — ради надёжности у проверяющего:
  браузерные разрешения на геолокацию легко ломаются и дают пустую ленту в самый неподходящий
  момент.
- Отказались от внутренних личных сообщений: реальная коммуникация всё равно уходит в
  мессенджеры, поэтому в профиле просто ссылка на телеграм/инстаграм.

Порядок реализации намеренно нестандартный: сначала пустой проект был доведён до рабочей
ссылки на Vercel (Neon + деплой + первый коммит), и только потом писались функции — чтобы
все проблемы со сборкой и переменными окружения вылезли в спокойный момент, а не за час до
дедлайна.

## Уникальные подходы

- **Лента строится на совпадении состояния, а не на подписках.** Показывает не тех, кого ты
  выбрал читать, а тех, кто рядом и в похожем настроении прямо сейчас.
- **Нельзя посмотреть чужой вайб, не заявив свой.** Переключатель вайба у вошедшего
  пользователя не просто фильтрует ленту — он меняет его собственное состояние. Посмотреть
  весь город, не переключая себя, можно только через отдельный режим «Все».
- **Счётчик активности учитывает свежесть статуса**, а не всех когда-либо зарегистрированных:
  считаются только те, кто отмечал вайб за последние 48 часов (`ACTIVE_WINDOW_HOURS`).

## Компромиссы

- Город хранится строкой, а не геокоординатами — проще, надёжнее, не требует разрешений
  браузера.
- Фильтрация ленты идёт через связь с автором (`Post.author.city`), без дублирования города
  в самом посте — на масштабе этого проекта это проще и не создаёт риска рассинхронизации
  данных при переезде пользователя в другой город.
- Своя авторизация (bcryptjs + подписанный JWT в cookie) вместо готового решения вроде
  NextAuth — меньше возможностей «из коробки», зато весь путь пароля и сессии полностью
  объясним, без магии сторонней библиотеки.
- ИИ-поиск по смыслу не реализован осознанно: обычный поиск по подстроке уже закрывает
  соответствующий пункт задания, а осмысленный поиск потребовал бы внешнего API-ключа
  и добавил бы точку отказа без явной необходимости для курсового проекта.

## Известные баги и проблемы

- Счётчик «сейчас в городе» считает только статусы за последние 48 часов, поэтому на
  засеянных демо-данных он будет плавно уменьшаться со временем, пока кто-то не зайдёт
  и не переключит свой вайб заново.
- Нет ограничения частоты запросов (rate limiting) — теоретически возможен спам постами
  или лайками с одного аккаунта.
- Neon на бесплатном тарифе «усыпляет» базу после простоя: самый первый запрос после паузы
  может занять несколько секунд, а в редких случаях — вернуть ошибку соединения, которая
  пропадает сама при повторной попытке. На активном сайте, когда база уже «тёплая», это
  не заметно.
- ИИ-поиск по смыслу не сделан — см. «Компромиссы» выше.
- Редактирование поста не меняет его вайб — пост навсегда остаётся с вайбом, который был
  у автора в момент публикации, даже если текст потом отредактирован.

## Обоснование выбора стека

- **Next.js (App Router) + TypeScript** — фронтенд и бэкенд в одном проекте. Требование
  «интегрируйте свой API» закрывается естественно: серверные маршруты в `app/api/...` — это
  и есть бэкенд, без отдельного сервера.
- **Vercel + Neon** — разворачиваются бесплатно и за минуты. Neon отдаёт отдельную пулинговую
  строку подключения для serverless-окружений, что важно для Vercel.
- **Своя авторизация** (bcryptjs + jose) вместо NextAuth — меньше магии, каждый шаг
  (хеширование пароля, подпись и проверка JWT) можно объяснить на защите одной фразой.
- **Prisma 6.19.3, а не последняя мажорная (8.x rc).** На момент разработки `npm install prisma`
  подтягивал `8.0.0-rc.13` — релиз-кандидат, в котором из `schema.prisma` убрали `url`/`directUrl`
  в пользу отдельного `prisma.config.ts` и драйвер-адаптеров. Для курсового проекта это
  неоправданное усложнение, поэтому версия зафиксирована на последней стабильной, которая
  поддерживает привычную схему из задания.
