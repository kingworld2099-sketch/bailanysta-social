## 0. Контекст и сроки

Это конкурсное тестовое задание для гранта образовательного курса. Дедлайн — **6 сентября**.
Работу оценивает ревьюер, который открывает публичный репозиторий на GitHub, читает README
и переходит по ссылке на задеплоенное приложение.

**Времени примерно один рабочий день.** Из этого следует главное правило:

> Лучше меньше функций, но всё работает, чем весь список и белый экран на деплое.

Критично:
- Приложение должно **открываться по ссылке и работать без ошибок**. Неработающий деплой хуже, чем его отсутствие.
- Обязательные уровни важнее бонусов. Сначала закрываем всё обязательное, потом добираем бонусы.
- Ревьюер зайдёт **как гость** (без входа) и как новый пользователь. В обоих случаях он должен
  сразу увидеть живое приложение с контентом, а не форму логина и не пустой экран.

## 1. Идея продукта

**Bailanysta** (от каз. «байланыс» — связь) — социальная сеть, где ты видишь не тех,
на кого подписан, а тех, кто **прямо сейчас в твоём городе и в том же состоянии, что и ты**.

Проблема: обычные соцсети показывают ленту по подпискам и по вчерашнему контенту.
Когда человек освободился вечером и хочет куда-то выбраться, он перебирает переписки
и в итоге остаётся дома — хотя в городе сотни людей хотят того же.

Решение: пользователь одним нажатием отмечает свой **вайб**. Лента показывает посты людей
из его города с тем же вайбом. Никаких подписок, друзей и заявок — связь возникает
из совпадения в моменте.

**Вайбы (ровно четыре):**

| Код | Название в интерфейсе |
|---|---|
| `MOVE` | На движе |
| `CALM` | Спокойно |
| `DRAINED` | Выжат |
| `WORK` | В работе |

## 2. Технический стек

Использовать именно этот стек, не заменять без согласования:

- **Next.js (App Router) + TypeScript** — фронтенд и бэкенд в одном проекте
- **Tailwind CSS** — стили
- **Prisma + PostgreSQL** — база данных
- **Neon** (neon.tech, бесплатный тариф) — хостинг базы
- **Vercel** — деплой
- Авторизация — **своя**, без внешних провайдеров

Почему так (это пойдёт в README):
- Next.js закрывает требование «интегрируйте свой API» — бэкенд живёт в том же проекте,
  а требование «внешние сервисы вызываются с серверной части» выполняется естественно,
  через серверные маршруты.
- Vercel + Neon разворачиваются бесплатно и за минуты, без своего сервера.
- Своя авторизация вместо NextAuth — меньше магии, проще объяснить на защите.

### 2.1. Обязательные технические решения (иначе деплой упадёт)

Это самые частые причины «репозиторий есть, а ссылка не работает». Соблюдать строго:

1. **Хеширование пароля — только `bcryptjs`, не `bcrypt`.**
   Обычный `bcrypt` — нативный модуль, он требует компиляции и регулярно ломает сборку
   на Vercel. `bcryptjs` — то же самое на чистом JavaScript, собирается везде.

2. **В `package.json` обязателен скрипт `postinstall` со значением `prisma generate`.**
   Без него Vercel собирает проект без клиента Prisma и билд падает с ошибкой,
   которой нет локально.

3. **Строка подключения к Neon — пулинговая (pooled).**
   В Neon есть два адреса базы. Для serverless нужен тот, что с `-pooler` в имени хоста,
   иначе база быстро упирается в лимит одновременных соединений и приложение начинает отваливаться.
   В `.env` держим две переменные:
   - `DATABASE_URL` — пулинговая, используется приложением;
   - `DIRECT_URL` — прямая, используется только миграциями Prisma
     (в `schema.prisma` прописать `directUrl`).

4. **Экземпляр Prisma Client — один на процесс** (глобальный singleton с проверкой
   `globalThis`), иначе в режиме разработки при горячей перезагрузке плодятся соединения.

5. **Все маршруты, где используется `bcryptjs` и работа с сессией, — Node runtime**
   (не Edge). Не добавлять `export const runtime = 'edge'`.

### 2.2. Сессия

- Подписанный **JWT** (библиотека `jose`, алгоритм HS256), секрет в переменной `SESSION_SECRET`.
- Хранится в cookie `bailanysta_session`: `httpOnly`, `sameSite=lax`,
  `secure` в продакшене, срок жизни 30 дней.
- В токене только `userId`. Всё остальное берём из базы.
- Проверка сессии — в серверных компонентах и в обработчиках маршрутов.
  Отдельный `middleware.ts` для авторизации **не делать** — лишний источник поломок.

## 3. Модель данных

```
User
  id            string, uuid
  username      string, UNIQUE   — логин для входа, латиница
  name          string           — отображаемое имя
  city          string           — город
  occupation    string?          — чем занимается (необязательно)
  bio           string?          — о себе (необязательно)
  contact       string?          — телеграм или инстаграм для связи
  passwordHash  string
  vibe          Vibe             — текущий вайб, по умолчанию CALM
  vibeUpdatedAt datetime         — когда вайб менялся последний раз
  createdAt     datetime

Post
  id         string, uuid
  authorId   -> User
  text       string             — до 500 символов
  vibe       Vibe               — вайб на момент публикации
  createdAt  datetime

Like
  id      string
  userId  -> User
  postId  -> Post
  (уникальная пара userId + postId)

Comment
  id        string
  authorId  -> User
  postId    -> Post
  text      string              — до 300 символов
  createdAt datetime

enum Vibe { MOVE CALM DRAINED WORK }
```

**Индексы:**
- `Post`: по `[vibe, createdAt]` и по `[authorId, createdAt]`
- `User`: по `[city, vibe, vibeUpdatedAt]`

**Удаление:** при удалении пользователя или поста связанные лайки и комментарии
удаляются каскадно (`onDelete: Cascade`).

### 3.1. Вход по логину, а не по имени

`name` не уникально: две Айгерим в базе — норма. Поэтому вход по имени невозможен.

- `username` — уникальный логин, 3–20 символов, только строчная латиница, цифры и `_`.
  При регистрации приводим к нижнему регистру и обрезаем пробелы.
- `name` — как человека видно в ленте, 2–40 символов, любые буквы.

На форме регистрации подписать поля понятно: «Логин (для входа, латиницей)»
и «Имя (его увидят другие)».

### 3.2. Город

Выпадающий список: Астана, Алматы, Шымкент, Караганда, Актобе, **Другой**.

При выборе «Другой» появляется текстовое поле «Введите город» — и в базу пишется
введённое значение. Слово «Другой» в базу **не сохранять**, иначе все такие
пользователи окажутся в одном несуществующем городе и увидят друг друга.

**Геолокацию не использовать.** Браузерные разрешения ломаются у проверяющего,
и он увидит пустую ленту. Город — поле в профиле.

## 4. Доступ и роли

Ролей нет. Есть два состояния: **гость** и **вошедший пользователь**.

### Что доступно гостю (без входа)

Гость **видит** всё содержимое: ленту, профили, поиск. Это принципиально — ревьюер
не должен упираться в форму логина.

- `/feed` — лента открыта на чтение. Переключатель вайба работает как обычный фильтр,
  ничей вайб при этом не меняется. Город по умолчанию — Астана.
- `/profile/[id]` и `/search` — открыты.
- Сверху ленты — неброская полоска: «Вы смотрите как гость» с двумя кнопками
  «Войти как демо» и «Создать аккаунт».

### Что требует входа

Создание поста, лайк, комментарий, смена своего вайба, редактирование профиля,
удаление своих постов.

Если гость нажимает такую кнопку — **не белый экран и не молчание**, а короткое
всплывающее окно: «Чтобы поставить лайк, нужно войти» с кнопками «Войти как демо»
и «Создать аккаунт».

### Демо-вход (обязательно)

Сид создаёт демо-пользователя: логин `demo`, пароль `demo1234`, имя «Аяна», город Астана.

- На `/login` — заметная кнопка **«Войти как демо»**: один клик, без ввода данных,
  сразу в ленту. Реализовать отдельным маршрутом `POST /api/auth/demo`.
- Логин и пароль демо-аккаунта продублировать в README.

Это самый дешёвый пункт во всём задании и самый заметный для оценки: ревьюер
попадает внутрь приложения за один клик.

## 5. Экраны и маршруты

### `/` — корень
Редирект на `/feed`. Отдельную титульную страницу не делаем — экономим время,
а объяснение идеи уместим в полоску для гостя и в README.

### `/register` — регистрация
Логин, имя, город (выпадающий список + поле для «Другой»), пароль.
Необязательные: чем занимаешься, о себе, контакт.
Ошибки показывать по-человечески: «Такой логин уже занят», а не код ошибки базы.

### `/login` — вход
Логин и пароль. Кнопка «Войти как демо». Ссылка на регистрацию.

### `/feed` — лента (главный экран)

- Сверху — **переключатель вайба**: четыре кнопки, активная подсвечена.
  - Для вошедшего пользователя нажатие **меняет его вайб** и сразу перестраивает ленту.
    Это осознанное решение: нельзя подсмотреть чужое состояние, не заявив своё.
    Оно идёт в README в раздел «уникальные подходы».
  - Для гостя это просто фильтр — менять нечего.
- Строка-счётчик: «Сейчас в Астане на движе — 12 человек». Правила счёта — в разделе 5.1.
- Тумблер **«Только мой вайб» / «Все»**. По умолчанию включён «только мой вайб».
  Он позволяет посмотреть весь город, не меняя своё состояние.
- Фильтр по городу: по умолчанию город пользователя (для гостя — Астана),
  можно переключить на «все города».
- Поле создания поста: текст + вайб (подставляется текущий) + **счётчик символов**
  (`0 / 500`), который краснеет на подходе к лимиту. Кнопка отправки заблокирована,
  если текст пустой или длиннее 500.
- Список постов: имя автора (ссылка на профиль), вайб, время («20 минут назад»),
  текст, лайк со счётчиком, комментарии.
- **Если после фильтров постов нет** — не белый экран, а понятное сообщение
  «Сейчас в Астане никого на этом вайбе» и кнопка «Показать все».

### `/profile/[id]` — чужой профиль
Имя, логин, город, вайб, чем занимается, о себе, кнопка «Написать» (ссылка на телеграм
или инстаграм, если контакт указан), все посты этого человека.
Если постов нет — «Пока ничего не публиковал».

### `/me` — свой профиль
То же самое плюс редактирование полей и создание постов. Только для вошедших;
гостя редиректим на `/login`.

### `/search` — поиск
Поиск постов по словам в тексте. Обычный поиск по подстроке без учёта регистра,
**без хэштегов**. Пустой запрос — подсказка «Введите слово: кофе, зал, прогулка».
Ничего не нашлось — «По запросу ... ничего не нашли».

Обоснование для README: хэштеги в 2026 году перестали быть инструментом поиска —
платформы ушли к пониманию смысла текста. Мы сознательно не стали делать устаревающую механику.

### 5.1. Счётчик «сейчас в городе»

Поле `vibeUpdatedAt` существует именно для этого — иначе счётчик врёт.

- Считаем пользователей, у кого совпадает город и вайб **и** `vibeUpdatedAt`
  не старше **48 часов**. Значение вынести в константу `ACTIVE_WINDOW_HOURS`
  в одном файле конфигурации, чтобы его было легко поменять.
- Склонения обязательны: «1 человек», «3 человека», «12 человек».
  Написать маленькую функцию-помощник, не городить «человек(а)».
- Если получилось ноль — вместо цифры показать «Пока никого — ты первый».

### 5.2. Обязательные страницы-заглушки

- `app/not-found.tsx` — понятная страница 404 с кнопкой «На главную».
- `app/error.tsx` — экран ошибки с кнопкой «Обновить».
- `app/loading.tsx` и скелетоны ленты.

Смысл простой: у ревьюера ни при каком сценарии не должно получиться белого экрана.

## 6. API (серверные маршруты)

Делать именно маршруты в `app/api/...`, а не только серверные экшены — на них
удобно ссылаться в README в разделе «интеграция своего API».

| Метод и путь | Что делает |
|---|---|
| `POST /api/auth/register` | регистрация, ставит cookie сессии |
| `POST /api/auth/login` | вход |
| `POST /api/auth/demo` | вход в демо-аккаунт без ввода данных |
| `POST /api/auth/logout` | выход |
| `PATCH /api/me` | правка профиля |
| `PATCH /api/me/vibe` | смена вайба, обновляет `vibeUpdatedAt` |
| `POST /api/posts` | создать пост |
| `DELETE /api/posts/[id]` | удалить свой пост |
| `POST /api/posts/[id]/like` | поставить или снять лайк |
| `POST /api/posts/[id]/comments` | добавить комментарий |
| `GET /api/search?q=` | поиск постов |

**Правила для всех маршрутов:**
- Проверять авторизацию на сервере. Никогда не доверять тому, что пришло с клиента:
  автор поста берётся из сессии, а не из тела запроса.
- Удалять и редактировать можно только своё — проверять владельца.
- Валидацию дублировать на сервере, даже если она есть на форме.
- Возвращать понятный JSON с полем `error` и корректный HTTP-код,
  не отдавать текст исключения наружу.

**Ограничения на ввод:**

| Поле | Правило |
|---|---|
| `username` | 3–20, латиница, цифры, `_`, уникален |
| `name` | 2–40 |
| `password` | минимум 6 символов |
| `city` | из списка либо непустая строка |
| `bio` | до 300 |
| `occupation`, `contact` | до 100 |
| текст поста | 1–500 |
| текст комментария | 1–300 |

## 7. Дизайн

- **Мобильный экран — основной.** Проверяющий откроет и на телефоне.
- Тёмная тема по умолчанию, светлая — переключателем в шапке. Выбор сохраняется в `localStorage`.
  Тему применять до первой отрисовки (маленький скрипт в шапке документа), иначе при загрузке
  будет заметная белая вспышка.
- Крупная типографика, много воздуха, никакой пестроты.
- Кнопки, переключатели и поля — в стиле iOS: скруглённые, мягкие тени, аккуратные тумблеры.
- Вайбы различать не только цветом, но и подписью.
- **Запрещено:** анимации, при которых контент исчезает или не появляется на телефоне.
  Появление блоков по скроллу не делать — на мобильных это регулярно ломается.
- Лоадеры и скелетоны при загрузке ленты (это отдельный бонусный пункт задания).
- Лайк — с мгновенной реакцией (оптимистичное обновление), но при ошибке сервера
  состояние откатывается назад.
- Заголовок вкладки, описание и иконка сайта — сделать. Без них проект
  выглядит незаконченным в первую же секунду.

## 8. Наполнение базы (обязательно)

Сид-скрипт `prisma/seed.ts`, запуск одной командой `npm run seed`.

- **15 тестовых пользователей** плюс демо-аккаунт из раздела 4.
- Большинство — Астана, несколько — Алматы, чтобы фильтр по городу было видно.
- Все четыре вайба представлены, но с перекосом: больше всего `MOVE` и `CALM`.
- Тексты постов — живые и бытовые, на русском: закрыл смену, ищу компанию на завтрак,
  еду в центр, хочу тишины. Не рекламные и не пафосные.
- У части постов уже есть лайки и комментарии.

**Даты — только относительно текущего момента.** Ни одной жёстко прописанной даты:
`createdAt` считать как «сейчас минус N минут или часов», `vibeUpdatedAt` — в пределах
последних нескольких часов. Иначе через неделю лента будет выглядеть мёртвой,
а счётчик активности покажет ноль.

Сид должен быть **перезапускаемым**: сначала чистит свои таблицы, потом наполняет заново.

Без наполнения ревьюер зайдёт в пустое приложение. Это самая частая причина низкой оценки.

## 9. Порядок работы

### Этап 0 — деплой в самом начале (не в конце!)

Это изменение относительно обычного порядка, и оно важное. Сначала поднимаем пустой
проект до рабочей ссылки, и только потом пишем функции.

1. Проверить окружение (Node.js, npm, git), доложить, чего не хватает.
2. Создать проект Next.js + TypeScript + Tailwind.
3. Создать репозиторий на GitHub, сделать первый коммит.
4. Завести базу в Neon, прописать `DATABASE_URL` и `DIRECT_URL`.
5. Задеплоить на Vercel и **открыть живую ссылку в браузере**.

Смысл: все проблемы со сборкой вылезут в спокойный момент, а не за час до дедлайна.
Дальше каждый готовый кусок просто уезжает на живой сайт.

### Этап 1 — обязательная часть

1. Схема Prisma, миграция, сид.
2. Регистрация, вход, демо-вход, выход, сессия.
3. Лента: создание постов, вывод, переключатель вайба, фильтры, счётчик, пустые состояния.
4. Профиль свой и чужой, редактирование профиля.
5. Гостевой режим и приглашение войти.

**Материал для раздела «процесс проектирования» — реальная история идеи, использовать её:**
- Первая версия концепции строилась вокруг постинга после смены. Отказались: автор работал
  барменом и знает, что в три ночи у человека нет сил ни на что.
- Рассматривали статичные интересы в профиле (музыка, кино, животные). Отказались:
  анкета врёт и почти не меняется, а состояние меняется каждый день — фильтр по нему
  остаётся живым.
- Рассматривали хэштеги. Отказались: индустрия ушла от них к смысловому поиску.
- Отказались от геолокации в пользу поля «город» — ради надёжности у проверяющего.
- Отказались от внутренних сообщений: реальная коммуникация всё равно уходит в мессенджеры.

**Материал для «уникальных подходов»:**
- Лента строится на совпадении состояния, а не на подписках.
- Нельзя посмотреть чужой вайб, не заявив свой: переключатель меняет твоё состояние,
  а не только фильтр. Наблюдать со стороны можно только через режим «Все».
- Счётчик активности учитывает свежесть статуса, а не всех зарегистрированных.

**Материал для «компромиссов»:**
- Город строкой вместо геолокации.
- Фильтрация ленты идёт через связь с автором, без дублирования города в посте —
  на масштабе задания это проще и не требует синхронизации данных.
- Своя авторизация вместо готового решения: меньше возможностей, зато всё понятно и объяснимо.

**Раздел «известные баги» писать честно.** Реальный список из двух-трёх пунктов ценится
выше, чем его отсутствие. Обязательно упомянуть:
- счётчик активности считает статусы за последние 48 часов, поэтому на засеянных
  демо-данных со временем он уменьшается;
- нет ограничения частоты запросов, теоретически возможен спам постами;
- всё остальное, что реально вырезали.

## 11. Переменные окружения

Файл `.env` — только локально, в `.gitignore`. В репозиторий кладём `.env.example`
с теми же ключами и пустыми значениями.

```
DATABASE_URL=      # пулинговая строка Neon (с -pooler), для приложения
DIRECT_URL=        # прямая строка Neon, для миграций Prisma
SESSION_SECRET=    # длинная случайная строка для подписи сессии
AI_API_KEY=        # только если делаем ИИ-поиск
```

Те же переменные прописать в настройках проекта на Vercel.
